# 생성형 AI 사용 기록

강의계획서의 AI 정책(사용 도구·모델, 프로젝트 관련 프롬프트, 활용 방식 제출)에 따른 기록이다. 제출한 모든 내용은 본인이 이해하고 설명할 수 있어야 한다.

## 사용 도구

| 시기 | 도구 / 모델 | 용도 |
|---|---|---|
| 3주 (주제 선정) | Codex | 후보 주제 발상, 독립 검토, 제안서 초안 (기록: `project_prep/_recommendation_work/`) |
| 3주 (주제 선정) | Claude Code (Claude Opus 5, Claude Fable 5.1) | 서브에이전트 브레인스토밍, 주제 재선정, 1페이지 제안서 작성 |
| 3~5주 | Claude Code (Claude Opus 5.5) | 피드백 반영 범위 조정, 스키마·함수·테스트·시드 생성기·설계 문서 작성 |
| 11월 (물리 설계 · 화면 구현) | Claude Code (Claude Fable 5.2) | 물리 설계 문서 작성·재검토, Django 운영 콘솔(화면·조회 SQL·테스트) 작성 |

## 주요 프롬프트 (요지)

- "피드백 반영해서 프로젝트 진행해보자" — 범위 조정안(`project_prep/scope_v2.md`)을 바탕으로 5주 설계와 7주 DB 구현을 진행하도록 요청
- (범위 조정 시) 교수 피드백 원문: 기능 축소, 로그인 이력 소규모로 먼저 검증, 관리 화면과 감사 타임라인 필요
- "다음은 이제 물리 제약" (모든 테이블 / 제약 명세 / 참조 무결성·삭제 정책), "최선임?", "너무 과하게 쓰거나 길게 쓰진 않았음?" — 물리 설계 문서 작성과 재검토·분량 축소 요청
- "django 화면 작업 시작" — 제출한 요구사항(REQ-05~16)의 운영 화면 구현 요청

## AI가 만든 것과 본인이 할 일

| 산출물 | AI가 한 일 | 본인 검토·보완 (작성 필요) |
|---|---|---|
| `db/*.sql` | 테이블·제약조건·함수·트리거·권한 초안 작성, 테스트 통과 확인 | |
| `tests/` | 정책·권한·동시성 테스트 작성 | |
| `scripts/seed.py` | 합성 데이터 생성 규칙 작성 | |
| `docs/` | ERD, 정규화 근거 문안 작성 | |
| `web/`, `console/`, `tests/test_web.py` | Django 설정, 운영 콘솔 화면·조회 SQL·거부 화면, 접근 통제·전이 테스트 작성 | |

설계 결정의 근거(왜 이 제약을 두었는지, 왜 이 잠금을 쓰는지)는 각 SQL 파일 주석과 `docs/05_normalization.md`에 적혀 있다. 발표·기말 전에 직접 읽고 설명할 수 있는지 확인할 것.
